# k3s with embedded etcd from the first node

The cluster starts with one server node on embedded etcd (`clusterInit`) instead of k3s's default SQLite, so that growing to more servers never needs a datastore migration. The planned growth is one, then two, then three servers, with any number of agents; the first server is implemented, joining is not yet. The cluster token is fixed from the first start: generated once by `backfabric keygen` into sops (`secrets/common.yaml`), unlike the host secrets (ADR 0010), because k3s encrypts its bootstrap data in etcd with it and restoring an etcd snapshot on a new server needs the original token. Two etcd servers have no fault tolerance (both are needed for quorum, and every reboot waits for a manual unlock, ADR 0004); the user accepted this, and adding the second node as an agent until a third server exists remains an option.
